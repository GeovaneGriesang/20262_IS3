01Visão Geral e Objetivos de Aprendizagem

Nesta aula, daremos o primeiro passo prático na construção dos projetos de software do semestre. O objetivo principal é dominar as rotinas do Git e do GitHub para garantir a rastreabilidade, o trabalho em equipe sem conflitos e a entrega contínua dos softwares às entidades parceiras de Venâncio Aires.

Objetivos de Aprendizagem

  • Compreender o funcionamento do controle de versão distribuído no fluxo de desenvolvimento.
  • Configurar o ambiente de desenvolvimento nos laboratórios do IFSul de forma segura.
  • Criar e estruturar repositórios no GitHub adicionando os membros da equipe e o professor como colaborador.
  • Dominar os comandos essenciais de ciclo de vida do código (status, add, commit, push, pull).
  • Compreender a utilidade e a nomenclatura de branches e arquivos .gitignore.

Os computadores dos laboratórios do IFSul Câmpus Venâncio Aires são utilizados por diversas turmas diariamente. Para evitar vazamento de credenciais ou sobrescrita acidental do trabalho de outros estudantes, siga rigorosamente as orientações abaixo:

  2. Sempre valide o usuário do Git antes de realizar qualquer commit.
  3. Ao finalizar a aula, remova seu Personal Access Token (PAT) do PC.
  4. Faça sincronização (push) de todos os dados antes de sair da sala.

Verificando e Configurando sua Identidade

Sempre que sentar em uma bancada do laboratório, siga esta sequência em vez de configurar direto: assim você confere quem está "assinando" os commits naquela máquina antes de sobrescrever qualquer coisa.

1. Inspeção prévia: verifique o nome e o e-mail configurados globalmente no momento:

bash
# Verificar o nome configurado globalmente
git config --global user.name

# Verificar o e-mail configurado globalmente
git config --global user.email
Diagnóstico: se o terminal devolver os seus próprios dados, o ambiente já está pronto. Se devolver os dados de outro(a) estudante (ou ficar em branco), é necessário atualizar a identidade antes de continuar.

Para visualizar todas as configurações globais ativas de uma vez (editor padrão, branch padrão etc.):

bash
git config --list --global

E para saber de qual arquivo cada configuração está sendo lida (do sistema, do usuário ou do repositório):

bash
git config --list --show-origin

2. Definição da identidade: configure a identidade apenas dentro da pasta do repositório do seu projeto, com --local: assim você não altera a configuração global da máquina nem afeta colegas de outros turnos.

bash
# Entre na pasta do seu projeto clonado
cd 20262_IS3_GrupoXX

# Configure a identidade APENAS para este repositório
git config --local user.name "Seu Nome Completo"
git config --local user.email "seu.email@academico.ifsul.edu.br"

03Entendendo os Conceitos sem Complicação

Para quem está lidando com controle de versão pela primeira vez, alguns termos podem parecer abstratos. Vamos traduzi-los para o nosso dia a dia de projeto:

O que é um Repositório?

Pense no repositório como a pasta inteligente do seu projeto. Além de guardar seus arquivos em Java, telas FXML e scripts SQL, ele guarda todo o histórico de alterações: quem alterou, quando alterou e o que exatamente foi modificado.

O que é um Commit?

Um commit é como uma foto (snapshot) do estado atual do seu projeto em um momento em que as coisas estão funcionando. Cada commit recebe uma mensagem explicativa do que foi construído ou corrigido.

Padronização de Commits (Conventional Commits)

Para manter o histórico do projeto organizado e fácil de entender, adotamos o padrão Conventional Commits: toda mensagem de commit segue a estrutura tipo: descrição, em que o tipo indica a natureza da alteração.

TipoQuando usarExemplo
feat:Nova funcionalidadefeat: adiciona tela de cadastro de usuário
fix:Correção de um bugfix: corrige validação de e-mail duplicado
docs:Alterações em documentaçãodocs: atualiza README com instruções de setup
style:Formatação, sem mudança de lógicastyle: ajusta indentação da classe Usuario
refactor:Reestruturação de código sem mudar comportamentorefactor: extrai validação para a classe Utils
build:Mudanças de build ou dependênciasbuild: adiciona dependência mysql-connector-j no pom.xml

O que é Branch Padrão (Main)?

Branch significa "ramificação". Quando criamos um repositório, o Git cria uma linha do tempo principal para o código: a branch main, onde reside o código estável e pronto para testes ou demonstrações para as entidades parceiras.

Na prática cotidiana, criamos branches secundárias (como feature/tela-login) para trabalhar em funcionalidades isoladas sem quebrar a versão principal que está funcionando.

Os Quatro Pilares do Git

Todo arquivo do seu projeto passa por até quatro lugares diferentes, nesta ordem:

Working Directory

A pasta de trabalho local no seu PC, onde você edita os arquivos normalmente.

Staging Area

A "mesa de preparação/fotografia": alimentada via git add, é onde você escolhe exatamente o que entrará no próximo commit.

Local Repository

O cofre de histórico local, atualizado a cada git commit; cada commit é uma foto permanente daquele momento.

Remote Repository

O servidor na nuvem (GitHub), sincronizado via git push; garante backup e permite que o grupo e o professor acompanhem o progresso.

Working Directory
──▶git add
Staging Area
──▶git commit
Local Repository
──▶git push
GitHub Remote

04Prática Guiada: Configuração Inicial do Projeto

Siga os passos a seguir no laboratório para iniciar a estrutura de um projeto JavaFX/NetBeans 28 com Git.

Passo 1: Inicialização do Repositório Local

No terminal do NetBeans ou do sistema operacional, na pasta raiz do seu projeto:

bash
git init

Passo 2: Criação do Arquivo .gitignore

Arquivos compilados, pastas .nbproject locais ou artefatos do NetBeans não devem poluir o GitHub. Crie um arquivo chamado .gitignore na raiz do projeto com o seguinte conteúdo:

.gitignore
/target/
/nbproject/private/
*.class
*.jar
*.log
.DS_Store

Passo 3: Adição e Primeiro Commit

bash
# Adiciona todos os arquivos válidos para a Staging Area
git add .

# Realiza o primeiro registro histórico
git commit -m "feat: estrutura inicial do projeto com NetBeans 28 e JavaFX"

Fluxo de Trabalho em Equipe: Git Pull, Push e Colaboração

Na prática, o grupo trabalha em paralelo no mesmo repositório. Veja como duas pessoas colaboram sem pisar no trabalho uma da outra:

Estudante A (criador/a): inspeciona a identidade local (git config user.name e git config user.email), cria a classe de domínio Categoria.java no projeto do grupo e envia a alteração para o GitHub:

bash
git add .
git commit -m "feat: adiciona classe de dominio Categoria"
git push origin main
Aviso de sincronia: Estudante A avisa o grupo que enviou a alteração para o GitHub; combinado é sempre melhor do que descoberto depois.

Estudante B (colaborador/a): antes de começar a trabalhar, busca as alterações mais recentes do repositório remoto:

bash
git pull origin main

Ao reabrir o projeto no NetBeans 28, a árvore de arquivos é atualizada automaticamente e a classe Categoria.java aparece no computador do Estudante B, sem precisar copiar nada manualmente.

O Estudante B insere um novo atributo na classe recebida (private Boolean ativo;) e envia a contribuição de volta:

bash
git add .
git commit -m "feat: adiciona atributo de status ativo na Categoria"
git push origin main

Padrões de Projeto Usados no TenisShop

Antes de olhar para a árvore de pacotes, vale entender por que ela é organizada assim.

O que é um padrão de projeto? Um padrão de projeto (design pattern) é uma solução conhecida e testada pela comunidade de programadores para um problema que se repete na hora de organizar código. Não é uma biblioteca para instalar nem um framework, é uma forma combinada de estruturar as classes para que o sistema fique mais fácil de entender, manter e evoluir. O TenisShop usa dois: o MVC (para organizar a aplicação inteira) e o Singleton (para controlar a conexão com o banco de dados).

MVC (Model, View e Controller). O TenisShop é um software único, sem cliente e servidor separados: tudo roda no mesmo programa, na mesma máquina, e o banco MySQL é apenas onde os dados ficam guardados. O MVC não muda isso; ele só organiza as responsabilidades dentro desse único programa, em três papéis:

Model

As classes de domínio (Usuario, Categoria) e a camada de acesso a dados (DAO). Representam os dados e as regras do sistema.

View

As telas construídas com JavaFX e FXML, que a turma vai criar nas próximas aulas. Mostram os dados e recebem a interação de quem usa o sistema.

Controller

As classes que recebem os eventos da tela (um clique, um envio de formulário), decidem o que fazer e atualizam o Model e a View.

Singleton. A classe ConexaoBanco usa esse padrão: em vez de abrir uma conexão nova toda vez que alguma parte do sistema precisa falar com o banco, ela guarda uma única conexão ativa (numa variável static) e a reaproveita enquanto estiver aberta. Isso evita o desperdício de abrir e fechar conexões repetidamente.

O que é uma classe de domínio? É o que fica dentro da pasta model/domain, que você já deve ter clicado no NetBeans. São as classes que representam os "substantivos" do problema, as coisas do mundo real que o sistema precisa controlar: um Usuario, uma Categoria, futuramente um Tenis, um Pedido. Cada classe de domínio guarda só os dados (atributos) e comportamentos simples ligados diretamente a esse conceito; ela não sabe nada sobre banco de dados ou tela.

O que é DAO (Data Access Object)? É o que fica dentro da pasta model/dao. São as classes responsáveis por conversar com o banco de dados: abrir conexão, executar comandos SQL, transformar linhas de tabela em objetos de domínio e vice-versa. A ideia do padrão DAO é isolar toda a lógica de persistência num lugar só, para que o restante do sistema não precise saber como os dados são salvos ou lidos, só pedir para o DAO fazer isso.

Conexão com o Banco de Dados: ConexaoBanco.java

Local: src/main/java/br/edu/ifsul/venancio/tenisshop/model/dao/ConexaoBanco.java

java
package br.edu.ifsul.venancio.tenisshop.model.dao;

import java.sql.Connection;
import java.sql.DriverManager;
import java.sql.SQLException;

/**
 * Classe responsável por gerenciar e fornecer conexões com o banco de dados MySQL.
 * Aplica o padrão de projeto Singleton simples para reaproveitamento da conexão.
 *
 * @author Geovane Griesang
 */
public class ConexaoBanco {

    private static final String URL = "jdbc:mysql://localhost:3306/tenisshop_db?useSSL=false&serverTimezone=UTC";
    private static final String USUARIO = "root";
    private static final String SENHA = "changeme"; // Insira a senha do MySQL do laboratório, se houver

    private static Connection conexao = null;

    /**
     * Obtém uma conexão ativa com o banco de dados.
     * @return Connection objeto de conexão SQL
     * @throws SQLException caso ocorra falha na conexão
     */
    public static Connection getConexao() throws SQLException {
        try {
            if (conexao == null || conexao.isClosed()) {
                Class.forName("com.mysql.cj.jdbc.Driver");
                conexao = DriverManager.getConnection(URL, USUARIO, SENHA);
                System.out.println("[INFO] Conexão com o banco de dados realizada com sucesso!");
            }
            return conexao;
        } catch (ClassNotFoundException e) {
            throw new SQLException("[ERRO] Driver JDBC do MySQL não foi encontrado.", e);
        }
    }

    /**
     * Fecha a conexão com o banco de dados caso esteja aberta.
     */
    public static void fecharConexao() {
        if (conexao != null) {
            try {
                if (!conexao.isClosed()) {
                    conexao.close();
                    System.out.println("[INFO] Conexão com o banco de dados encerrada.");
                }
            } catch (SQLException e) {
                System.err.println("[ERRO] Falha ao fechar a conexão: " + e.getMessage());
            }
        }
    }
}

package br.edu.ifsul.venancio.tenisshop;

import br.edu.ifsul.venancio.tenisshop.model.dao.ConexaoBanco;
import java.sql.Connection;
import java.sql.SQLException;

/**
 * Classe de inicialização e teste de infraestrutura da aplicação TenisShop.
 *
 * @author Geovane Griesang
 */
public class TenisShop {

    public static void main(String[] args) {
        System.out.println("=========================================");
        System.out.println("   Iniciando Aplicação TenisShop         ");
        System.out.println("=========================================");

        try {
            Connection conn = ConexaoBanco.getConexao();
            if (conn != null && !conn.isClosed()) {
                System.out.println(">>> Teste de Conexão: SUCESSO!");
            }
        } catch (SQLException e) {
            System.err.println(">>> Teste de Conexão: FALHA!");
            System.err.println("Detalhes do erro: " + e.getMessage());
        } finally {
            ConexaoBanco.fecharConexao();
        }
    }
}

Para garantir que o grupo concluiu satisfatoriamente as atividades previstas na Aula 02 (que compõem a avaliação processual contínua de 30% da nota final), verifique os pontos abaixo antes do término da aula:

  • Projeto NetBeans 28 / JavaFX criado, versionado e sincronizado (git push) com sucesso na branch padrão main.
